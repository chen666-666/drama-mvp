# Top3 自动补集操作与启用说明

正式功能已部署，2026-11-04按用户明确要求开启网页与独立补集进程，配置版本 `discovery-enable-20261104T080323Z`。接口与心跳均确认开启，旧榜单尚未自动关联。真实来源多页目录、同作者混发及不限时间搜索仍未完成验收，需以实际任务结果核对；开启不代表全剧完整性或来源质量已验收。

## 管理员操作

线上已开启，本机默认仍关闭。后续环境建议先完成下文的真实来源验证；网页与独立补集进程须同时配置 `DRAMA_EPISODE_DISCOVERY=1`，使用同一个数据库和同一个 DouK 桥接实例。普通生成与任务流程生成的正式榜单都会在保存事务内登记实际入选作品；草案、游客访问及公开 GET 不登记。

旧榜单不会自动关联。在“视频管理”选择实际榜单及作品，点击“为本榜单启动补集”。同一作品重复入选共享一个协调任务，但每个榜单各有独立的目录同步开关。

- **更新剧集**：重新读取代表视频的公开身份，检查首页新增；新增检查与历史继续分别保存游标。连续读取到两页已知视频形成的重叠边界，或有效末页、预算上限，再保留下一步位置。
- **继续查找**：在本轮新预算下推进已提交的历史位置，不重跑已经完成的目录页。登录、验证、解析问题及租约中断不会自动恢复。
- **暂停整部作品共享查找**：停止该作品全部关联榜单的后续请求。已发出的响应可返回，但不能在失去执行资格后继续同步。
- **暂停本榜单同步**：停止向当前目录追加；其他仍启用的榜单关联可以继续共享查找。所有关联都暂停后，工作任务也停止后续请求。
- **重新核对身份与维护剧名别名**：先暂停共享查找，再填写最多三个人工确认的别名。作者、作品归属或可信合集变化时，旧来源进度与观察仍保留，重新核对代表视频后再查找。

同作者且同可信合集，或同作者且明确命中已确认剧名/别名的视频，会作为**待核验、访问范围未知**的条目追加。仅有“第几集”等泛称、异作者、身份冲突、预告和合集保留在线索中，不能直接计为单集补齐。可核对公开来源后用已有手动链接入口加入目录，再逐项核验。

补集不调用第一步搜索导入，不受七天窗口或五万点赞门槛截断，也不修改 `Episode`、`SearchHit`、`MetricSnapshot` 或榜单快照。第一步排名规则保留。集号只作提示，未知总集数不根据最高集号推断；来源读完不代表全剧完整。

确认目录公开正片后，沿用原有试下载、明确选择准备范围、自动校验和连续快审。后台后来新增的条目不会扩入已确认范围。已结束的任务提供“为新增剧集新建补充准备流程”，原任务仍保持已完成，新流程须重新选择范围。目录审批和媒体人工通过是两项独立结论。

## 运行与请求控制

本机 `start.ps1` 隐藏启动独立补集进程，日志为 `data/logs/discovery.out.log` 与 `discovery.err.log`；也可单独运行 `start-discovery.ps1`。管理 Compose 增加 `discovery-worker`。心跳为 `data/discovery-worker.json`，系统页可查看进程及开关状态。public 模式拒绝启动该进程。

补集进程按页领取和轮转。数据库保存执行者、90秒租约及10秒续租心跳；只有当前执行者能保存一页。任务失效租约标记中断并等待管理员继续，不抢占有效租约。请求前保留预算，响应后在短事务内同时保存视频、观察、匹配、目录追加和游标；写入失败保留原位置。

每轮最多50次请求或10分钟，计入排队和重试；剩余时间不足一次有界请求时提前停止。初始分配为详情2次、合集22次、主页18次、补漏搜索8次。先给适用阶段执行机会，完成阶段的余额可转给未完成阶段。详情最多2次；搜索最多4组、每组最多2次；临时网络错误同一页最多尝试3次，重试前分别等待2秒、5秒，仍受阶段及总预算约束。

补漏搜索显式 `publish_time=0`，使用已确认剧名、人工别名、原作者；目录已明确总集数且人工核对时，可以加入明确缺集号组合。各来源与对象独立记录位置。缺字段、错误类型、异常空页、重复或循环游标都不能当成有效末页。

所有搜索、详情、目录和媒体解析请求经过同一 DouK 桥接的先进先出闸门，相邻开始时间至少2秒，一次只执行一个解析请求。CDN 文件流继续由原下载进程控制。账号返回登录或验证限制后，闸门保存不含凭证的暂停状态，桥接重启也不自动解除。在系统页处理登录或验证后，明确点击“恢复共享来源请求”，再分别继续相关任务。

当前只支持单个桥接实例；多实例前须增加跨实例协调。F2、其他API、定时追更和无人值守发布均未接入。

## 数据迁移与回退

新增 `009_episode_discovery`，依赖008，仅新增六张私有表：协调任务、来源进度、发现视频、观察记录、作品匹配和榜单关联。不回填旧榜单或重写历史记录。迁移版本检查已同步；迁移工具仍先备份、在数据库副本升级并逐字段校验既有表，再处理实际库。

独立 public 构建使用原字段白名单，新私有表保持空；游客接口不返回任务、证据或诊断。公开媒体仍检查实际入选、目录 approved/public、任务 verified、人工 passed、路径、大小和摘要。

上线应以服务器有效镜像标签、实际文件及 `data/deploy/current-ui-release.json` 为基线制作增量，保留线上其他修改；不能直接覆盖整个本机工作区。至少同步新路由、服务、模型、009迁移、两个管理页面及共用资源、补集worker、DouK桥接与调度模块、Compose。`Dockerfile.douk` 已加入调度模块，管理部署文件清单已加入任务与补集路由。

发布前备份应用文件、镜像和SQLite，核对活动搜索、准备、快审和补集租约，在正式库副本预演009并比对既有业务表。先保持开关关闭，小范围完成真实来源验收后再启用新榜单；旧榜单须主动关联。

回退先关闭网页和worker中的 `DRAMA_EPISODE_DISCOVERY`，停止补集worker领取，并在需要时暂停已有任务。保留009、新发现记录、追加条目与上线后的人工结论。应用回退必须使用兼容009版本检查的镜像；完整旧镜像只接受008，不能直接指向已升级数据库。若必须还原数据库，应在维护窗口逐项处理上线后业务数据，不直接覆盖备份、不执行降级删除新表。本迁移主动拒绝破坏性 downgrade。
